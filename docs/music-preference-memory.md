# Music preference memory rollout

This change is additive and deliberately inactive until the PR is approved. It does not restart any Hermes gateway or play audio.

## Architecture

- PostgreSQL `music` remains the sole operational source of truth.
- Existing `music.artist_names` is read for canonical artist resolution and is not modified.
- `preference_interactions` stores auditable request/preference evidence.
- `playback_lifecycle` stores status transitions without increasing request frequency.
- `knowledge_items` keeps sourced music facts and assistant recommendations separate from John’s preferences.
- Effective views remove forgotten, expired, corrected, and retracted evidence.
- Jev receives only the user text and returns bounded kind/scope/polarity choices. Entity names are never generated by the classifier.

## Approval-gated activation

Do not run these steps before GitHub approval.

1. Install the approved package into the music profile runtime.
2. Create the least-privilege NOLOGIN role:

   ```bash
   psql "$ADMIN_DSN" -v ON_ERROR_STOP=1 -f deploy/create_music_preferences_role.sql
   ```

3. Apply the additive schema twice (the second pass verifies idempotency):

   ```bash
   psql "$ADMIN_DSN" -v ON_ERROR_STOP=1 -f deploy/music_preferences.sql
   psql "$ADMIN_DSN" -v ON_ERROR_STOP=1 -f deploy/music_preferences.sql
   ```

4. Grant only the new objects plus read-only artist resolution:

   ```bash
   psql "$ADMIN_DSN" -v ON_ERROR_STOP=1 -v app_role=music_memory_app -f deploy/music_preferences_grants.sql
   psql "$ADMIN_DSN" -v ON_ERROR_STOP=1 -c 'GRANT music_memory_app TO john'
   ```

5. Add these values to the wrapper-level `env-profiles/local.env` or `prod.env` used by the music gateway (never a repository `.env`):

   ```text
   HERMES_MUSIC_MEMORY_DSN=dbname=palladium user=john host=/home/john/projects/postgres-hosting.workspace/data/postgres-socket
   HERMES_MUSIC_MEMORY_ROLE=music_memory_app
   ```

6. Install `skills/music-domain/SKILL.md` into the music profile only after preserving any local profile-only additions.
7. Dry-run legacy reconciliation, review counts, then apply exactly once. Both commands are idempotent; the first performs no writes. The reviewed 2026-09-27 dry run read 19 rows and produced 15 logical requests plus 19 lifecycle events: two rows explicitly marked `counts_toward_frequency=false` and two same-entity terminal status updates were folded into earlier requests. The old derived JSON count of 17 is therefore not imported as authoritative state.

   ```bash
   hermes-music-memory reconcile-jsonl /home/john/.hermes/profiles/music/data/music_requests.jsonl --person john
   hermes-music-memory reconcile-jsonl /home/john/.hermes/profiles/music/data/music_requests.jsonl --person john --apply
   ```

8. Verify the role cannot read unrelated schemas, then verify `context`, `inspect`, correction, retraction, and forgetting using non-production fixtures in a temporary database.
9. Restart only the music gateway, and only with explicit interruption authorization.
10. Ask John for one physical voice check. Tool dispatch is not audible-playback confirmation.

## Rollback

Stop writes by removing the two runtime environment variables and restoring the previous music skill. The additive tables can remain dormant. Do not drop `music.artist_names` or any existing schema object. Database object removal requires a separate reviewed migration.
